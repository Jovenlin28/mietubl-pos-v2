# Contributing Guide

Thanks for taking the time to contribute!

## Branching model
- Base branch: `master`
- Create feature branches from `master`.
- For automation/AI-generated changes, use the format: `/feature/AI-YYYY-MM-DD-HHMMSS`.
- For human work, use: `feature/<short-desc>` or `fix/<short-desc>`.

## Commit messages
Use Conventional Commits where practical:
- `feat: add sales dashboard widgets`
- `fix: correct date parsing in invoice table`
- `docs: update README with setup steps`

## Development checklist
Before opening a PR:
- [ ] App builds successfully: `npm run build`
- [ ] Dev server runs locally: `npm run dev`
- [ ] Docs/tests updated if you changed behavior
- [ ] Screenshots or notes included for visible UI changes

## Pull requests
- Target branch: `master`.
- Keep PRs small and focused.
- Provide a clear description of the change and any manual testing steps.

Thanks again for contributing and improving this project!
